# v2.0 Pack 数据面升级

## 范围

本次升级只替换运输盘数据面。Edge 与 Center 的 HTTP 控制接口、任务状态机、对象调度 SQL、ProgressAggregator 和 WebSocket payload 保持不变。

运输盘统一使用 `protocol.version = 2.0.0` 和 `manifest_version = 2.0.0`。本次为整体切换，不保留旧对象文件布局的导入分支。

## 盘内布局

```text
rustfs-transfer/
  data/packs/pack-<export_job_id>.dat
  manifests/export_manifest.json
  manifests/export_manifest.sha256
  manifests/export_manifest.hmac
  disk_info.json
```

一个 pack 连续保存 AES-256-GCM 加密记录。记录使用固定 8 MiB 明文上限；每条记录拥有独立 nonce、tag、AAD、明密文 SHA-256 和 pack 偏移。对象可以由多个连续记录组成。

## 一致性

- Edge 只在对象全部记录写入 pack、pack 文件同步完成后，才把原有 `export_object` 标记为 `EXPORTED`。
- 封盘前同步 pack，再原子写入 manifest、摘要、基于 `disk_data_key` 的 HMAC 和 `disk_info.json`；Center 在创建导入任务前验证 HMAC。
- Center 对每条记录校验范围、密文摘要、AES-GCM tag 和 AAD；对象全部记录合并后校验整体明文 SHA-256，成功上传并写入 `object_ledger` 后才计入完成。
- `.partial` pack 仍由既有恢复准入阻断；完整 pack 不会出现在 manifest 之前。

## 数据库

Edge 为 `export_object` 新增 `storage_layout` 与 `pack_records_json`，作为 pack 定位和恢复账本；不改变 `export_job`、`export_object` 状态含义。Center 保持 `import_job` 和 `object_ledger` 的权威语义，pack 定位信息来自摘要和 HMAC 保护的 manifest。

## 非目标

- 不更改 WebSocket 字段、推送节奏或任务状态。
- 不更改对象调度、多盘分配和 RustFS 源对象保护逻辑。
- 本轮不以性能数字作承诺；目标环境仍需执行 USB/VM、源端读取与 fsync 基线压测。
