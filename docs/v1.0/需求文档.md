## 1. 项目背景

当前存在多个边缘服务器，每台边缘服务器部署独立 RustFS，用于本地对象存储。中控端只有一个，需要将多个边缘端 RustFS 中的数据，通过运输硬盘离线拷贝并导入到中控端 RustFS。

## 2. 项目目标

项目需要完成以下目标：

- 项目必须在启动后 3 天内完成开发、联调、部署并上线可用。
- 边缘端自动识别已注册运输硬盘。
- 边缘端自动从本地 RustFS 导出对象数据到运输硬盘。
- 边缘端导出时避免拷贝仍在上传或正在变化的对象。
- 支持多个运输硬盘并行拷贝。
- 运输硬盘封盘后，中控端自动识别并导入。
- 中控端根据边缘端信息创建或复用对应归档存储桶。
- 中控端导入时支持去重，避免重复导入对象。
- 两端前端页面实时展示硬盘状态、任务状态、进度、速度、当前文件和异常。
- 所有离线交接必须通过统一运输盘协议完成，避免边缘端和中控端协议不一致。

- 单个对象大于单块运输盘容量时，支持跨多个运输盘分块导出和导入。
- 导出和导入任务进度实时展示。
- 任务失败后的基础重试和恢复。

## 4. 角色与职责

### 4.1 中控端

中控端是运输盘注册、导入和最终状态判断的权威端。

中控端需要负责：

- 注册运输硬盘。
- 初始化运输硬盘。
- 维护边缘站点信息。
- 识别插入的运输硬盘。
- 判断运输硬盘是否已注册。
- 判断运输硬盘是否可以初始化、导入或复用。
- 导入已封盘运输硬盘中的数据。
- 将数据写入中控端 RustFS。
- 根据对象账本避免重复导入。
- 导入完成后标记运输硬盘已导入，并触发清理和重新初始化流程。
- 向中控端前端实时推送导入状态。

### 4.2 边缘端

边缘端负责从本地 RustFS 导出数据，并按协议写入运输硬盘。

边缘端需要负责：

- 配置站点名称、站点编码、中控授权信息、RustFS S3 信息和数据库信息。
- 识别插入的运输硬盘。
- 向中控端校验运输硬盘是否已注册。
- 判断运输硬盘是否可用于本次导出。
- 扫描本地 RustFS 对象。
- 判断对象是否稳定，避免导出正在上传或变化的对象。
- 将待导出对象分配到一个或多个运输硬盘。
- 并行拷贝多个运输硬盘。
- 记录导出任务进度和对象状态。
- 导出完成后封盘。
- 边缘端本地对象生命周期在封盘后结束，`export_object.status` 不保存中控导入结果；中控是否已入库通过中控端账本或只读按需查询接口获取。
- 向边缘端前端实时推送拷贝状态。

### 4.3 运输硬盘

运输硬盘是边缘端和中控端之间的离线数据载体。

运输硬盘需要承载：

- 运输盘身份信息。
- 当前运输盘状态。
- 来源边缘端信息。
- 对象数据。
- 对象元数据。
- 对象清单。
- 校验信息。
- 导出和导入日志。

详细运输盘协议见：[开发协议契约.md](开发协议契约.md)。

## 5. 核心业务流程

### 5.1 中控端初始化运输硬盘

```text
人工插入运输硬盘
-> 中控端识别硬盘
-> 判断硬盘是否已注册
-> 未注册则人工注册
-> 初始化硬盘
-> 写入运输盘协议信息
-> 标记为可交付边缘端使用
```

### 5.2 边缘端导出数据

```text
人工插入已注册运输硬盘
-> 边缘端识别硬盘
-> 向中控端校验硬盘权限
-> 判断硬盘是否可写入
-> 扫描边缘端 RustFS
-> 过滤正在上传或变化的对象
-> 过滤已导出对象
-> 根据硬盘容量编排对象
-> 多盘并行拷贝
-> 生成对象清单和校验信息
-> 封盘
-> 前端提示可拔盘
```

### 5.3 中控端导入数据

```text
人工插入已封盘运输硬盘
-> 中控端识别硬盘
-> 校验硬盘注册信息
-> 校验运输盘协议和对象清单
-> 根据边缘端编码创建或复用归档存储桶
-> 按对象清单导入中控 RustFS
-> 跳过已导入对象
-> 导入完成后标记本次运输硬盘已导入
-> 清理运输硬盘中的本次封存数据
-> 重新初始化硬盘并写入新的 disk_info.json
-> 标记硬盘可交付边缘端复用
```

清理和重新初始化失败规则：

- 导入完成后，`import_job.status = DONE` 不得因后续清理或重新初始化失败而回滚。
- 盘内 `disk_info.json.status.code = IMPORTED` 必须保持，直到重新初始化全部成功后，最后一步才能写为 `INITIALIZED`。
- 清理或重新初始化失败时，该盘不得再次导入、不得交付边缘端写入，只允许中控端继续清理或重新初始化。
- `CLEANING`、`REINITIALIZING` 只能作为运行态或前端展示态，不得写入盘内 `disk_info.json.status.code`。

## 6. 功能需求

### 6.1 运输硬盘管理

- 系统必须识别 Linux 上新插入和拔出的运输硬盘。
- 中控端必须支持运输硬盘注册。
- 中控端必须支持运输硬盘初始化。
- 边缘端必须拒绝未注册运输硬盘。
- 边缘端必须拒绝存在未导入封存数据的运输硬盘。
- 中控端必须能识别已封盘运输硬盘并进入导入流程。
- 已导入运输硬盘必须先清理封存数据并重新初始化，才能交付边缘端复用。
- 已导入运输硬盘在清理或重新初始化失败时必须保持不可复用，后续只能由中控端继续清理或重新初始化，不得重复导入本次封盘数据。

### 6.2 边缘端 RustFS 数据扫描

- 边缘端必须通过 S3 API 访问本地 RustFS。
- 边缘端必须统计 RustFS 对象数量和容量。
- 边缘端必须支持按对象导出。
- 边缘端必须保留源对象 bucket、object key 和元数据。
- 边缘端必须能识别对象是否稳定，避免导出正在上传或变化的对象。

### 6.3 多运输盘并行导出

- 边缘端必须支持多个运输硬盘同时执行导出任务。
- 同一个对象不得被重复分配到多个运输硬盘；边缘端必须使用 PostgreSQL 行级锁和唯一约束保证该规则，不能只依赖内存锁或 Worker 自觉判断。
- 每块运输硬盘必须独立记录进度、速度、当前对象和异常。
- 运输硬盘空间不足时，不得影响其他运输硬盘继续拷贝。
- 运输硬盘对象容量编排必须预留协议文件、元数据、日志、加密开销和安全余量，不能按硬盘总容量或当前全部剩余空间直接分配对象。
- 写盘过程中出现磁盘满或空间不足时，只允许失败当前对象或停止当前运输硬盘继续分配；已经完整写入并校验通过的对象必须保留，不得因单个对象写满而判定整盘数据损坏。
- `.partial` 临时文件只表示未完成对象，恢复扫描和封盘前必须删除或隔离；清理失败时不得封盘、不得导入，必须进入人工处理。
- 单个对象失败时，不得影响其他对象继续处理。
- 单个对象大于单块运输盘容量时，必须按分块写入多个运输硬盘，并在清单中记录分块组、顺序、偏移、大小和校验值。
- 跨盘分块默认按 `10 GiB` 切分；除最后一个分块外，每个分块大小必须为 `10 GiB`。如果规划后单对象分块数量超过 `1,000,000`，必须拒绝导出该对象并记录明确错误。

### 6.4 中控端导入

- 中控端必须支持多个运输硬盘并行导入。
- 中控端必须校验运输盘协议、对象清单和对象完整性。
- 中控端必须根据来源边缘端编码导入到对应归档存储桶。
- 中控端必须保留边缘端原始文件结构。
- 中控端必须基于对象账本去重。
- 中控端必须能按清单合并跨盘分块对象，并在全部分块校验通过后再导入中控 RustFS。
- 跨盘分块对象的任一分块盘单独导入完成时，不得视为源对象已完成归档；只有同一 `chunk_group_id` 的全部分块到齐、校验通过、合并上传成功并写入 `object_ledger` 后，源对象才算导入完成。
- 中控端导入失败时，不得将运输硬盘标记为已导入。

### 6.5 多边缘端归档

多个边缘端 RustFS 数据最终合并到一个中控端 RustFS。

归档规则：

- 每个边缘端对应一个中控归档存储桶。
- 中控端根据边缘端编码识别来源。
- 如果归档存储桶不存在，中控端自动创建。
- 如果归档存储桶已存在，中控端直接复用。
- 同一边缘端内必须保留原始 bucket 和 object key 结构。

归档方式：

```text
中控 bucket: archive-{edge_code}
中控 key: {source_bucket}/{source_object_key}
```

### 6.6 实时状态展示

边缘端前端必须展示：

- 当前 RustFS 对象数量和容量。
- 已识别运输硬盘列表。
- 每块运输硬盘状态。
- 多盘并行拷贝总进度。
- 每块运输硬盘独立拷贝进度。
- 当前正在拷贝的文件名。
- 当前文件剩余字节数。
- 当前运输盘剩余待拷贝字节数。
- 整体剩余待拷贝字节数。
- 拷贝速度。
- 异常原因。

中控端前端必须展示：

- 已识别运输硬盘列表。
- 运输硬盘注册状态。
- 运输硬盘是否可初始化。
- 已封盘待导入运输硬盘。
- 多盘并行导入总进度。
- 每块运输硬盘独立导入进度。
- 当前导入对象。
- 导入速度。
- 导入完成状态。
- 异常原因。

WebSocket 事件结构见：[开发协议契约.md](开发协议契约.md)。

## 7. 状态要求

运输硬盘状态必须统一，不能由边缘端和中控端各自解释。

运输硬盘状态包括：

- 未注册。
- 已注册。
- 已初始化。
- 边缘拷贝中。
- 已封盘待导入。
- 中控导入中。
- 已导入待复用。
- 异常。

详细状态码、写入方、允许动作和禁止动作见：[开发协议契约.md](开发协议契约.md)。

## 8. 数据要求

- 对象必须按对象粒度导出和导入。
- 必须保留原始 bucket。
- 必须保留原始 object key。
- 必须保留对象元数据。
- 必须记录对象大小、ETag、最后修改时间和校验信息。
- 导入中控端后，必须能追溯对象来源边缘端。
- 每次封盘必须有唯一封盘批次 ID（`seal_id`），用于区分同一运输盘在不同复用周期内产生的不同封盘数据。
- 已导入对象必须有账本记录。
- 已导入对象的权威记录只保存在中控端 `object_ledger`；边缘端不得把本地 `export_object.status` 改为 `IMPORTED`。
- 重复导入同一对象时必须跳过。

数据库设计见：[数据库设计.md](数据库设计.md)。

## 9. 安全要求

- 边缘端禁止删除 RustFS 源数据。
- 边缘端禁止修改 RustFS 源对象。
- 边缘端只能对 RustFS 执行对象扫描、对象查询和对象下载。
- 未注册运输硬盘不得被边缘端使用。
- 未导入封盘运输硬盘不得被清理。
- 运输盘协议必须能防止两端状态误判。
- 运输盘落盘数据必须使用 AES-256 加密。

## 10. 异常处理要求

- 硬盘插入后识别失败，前端必须展示失败原因。
- 未注册硬盘插入边缘端，前端必须提示无权限。
- 存在未导入封存数据的硬盘插入边缘端，必须禁止清理和写入。
- 拷贝过程中硬盘拔出，任务必须进入异常状态，并记录标准错误码 `DISK_REMOVED`。
- 导入过程中硬盘拔出，任务必须进入异常状态，并记录标准错误码 `DISK_REMOVED`。
- 拷贝或导入过程中发生强行拔盘、断电或服务重启后，运输盘重新插入时必须先记录 `RECOVERY_REQUIRED`，再按盘内 `disk_info.json.status.code`、本地任务账本和中控导入账本进行恢复判定，不能只按盘内残留状态直接继续任务。
- 盘内残留 `EDGE_COPYING`、`CENTER_IMPORTING` 或存在 `.partial` 临时文件时，必须进入恢复检查流程；恢复检查通过前不得进入新的导出、导入、清理或重新初始化流程。
- 对象源端发生变化时，该对象本轮不得导出，并记录 `SOURCE_CHANGED`。
- 对象拷贝失败时，必须记录失败原因和标准错误码。
- 中控导入失败时，不得标记硬盘已导入；manifest 非法必须记录 `MANIFEST_INVALID`，校验值不一致必须记录 `CHECKSUM_MISMATCH`，解密失败必须记录 `DECRYPT_FAILED`。
- 运输盘协议版本不兼容时必须拒绝进入任务池，并记录 `PROTOCOL_VERSION_UNSUPPORTED`。
- 运输盘运行时检测到非 `ext4` 文件系统时必须拒绝进入任务池，并记录 `FILESYSTEM_UNSUPPORTED`。

## 11. 非功能需求

- 两端程序均部署在 Linux 系统。
- 两端程序必须支持开机自启动。
- 两端程序必须支持任务失败后恢复。
- 拷贝和导入进度刷新间隔不得超过 1 秒。
- 运输盘热插拔识别必须自动触发。
- 系统日志必须能辅助定位硬盘识别、拷贝、封盘、导入失败问题。

## 12. 验收标准

- 中控端能够注册和初始化运输硬盘。
- 边缘端插入未注册硬盘时会拒绝使用。
- 边缘端插入已初始化硬盘后能够自动开始导出。
- 边缘端能够同时向多个运输硬盘拷贝对象。
- 前端能够看到多盘拷贝进度、当前文件名和剩余字节数。
- 边缘端不会导出正在上传或变化的对象。
- 封盘运输硬盘插入中控端后能够自动导入。
- 中控端能够同时导入多个运输硬盘。
- 中控端不得并发导入同一块运输硬盘的同一封盘批次；同一 `disk_id + seal_id` 只能有一个活动导入任务。
- 中控端按边缘端编码创建或复用归档存储桶。
- 中控端导入后保留原始 bucket 和 object key 结构。
- 重复插入已导入硬盘不会重复导入对象。
- 导入完成后运输硬盘可进入清理和重新初始化流程，完成后边缘端才能复用。

## 13. 已确认决策

### 13.1 已确认决策

- 运输硬盘不允许边缘端自动清盘。
- 运输盘落盘数据必须使用 AES-256 加密。
- 单个对象大于单块运输盘容量时，需要分块到多个运输硬盘处理。
- RustFS 导出范围为全部 bucket。
- 只做对象级重试，不做单对象断点续传。
- 中控端前端和边缘端前端独立部署。

### 13.2 授权码用途

中控端和边缘端之间的授权码只用于 HTTP API 鉴权，不直接用于文件加密。

职责边界：

- API 鉴权：使用边缘端授权码或 API secret，校验边缘端是否允许调用中控接口。
- 协议签名：只由中控端使用中控签名密钥签名 `disk_info.json` 中的中控基础字段和密钥绑定字段。
- 文件加密：使用独立的数据加密密钥，不复用授权码。

原因：

- 授权码泄露时，只需要吊销接口权限，不应导致已落盘数据全部可解密。
- 文件加密密钥需要按运输盘或导出任务轮换，和接口鉴权生命周期不同。

字段约定：

```text
edge_auth_secret：边缘端调用中控 HTTP API 的鉴权密钥；中控端使用本机主密钥或部署环境密钥加密保存在 `edge_site.auth_secret_ciphertext`，不新增独立鉴权密钥表；边缘站点注册后禁止重置、替换或轮换。
disk_data_key：中控端为每次运输盘初始化生成的数据加密密钥，用于 AES-256 加密运输盘对象数据；该密钥不按时间过期，随运输盘本次导出、封盘、导入和重新初始化生命周期流转，导入完成并重新初始化后旧密钥作废。
center_key_id：写入 disk_info.json，用于中控端校验自身写入的 center_signature。
data_key_id：写入 disk_info.json 和 manifest，用于中控端导入时在数据库中找到对应数据加密密钥。
```

### 13.3 运输硬盘 SN 使用规则

不得只依赖硬件 SN 作为运输盘唯一身份。

处理规则：

- 中控端注册硬盘时读取 SN、容量、文件系统、设备路径等信息作为辅助识别。
- 中控端初始化时生成稳定的 `disk_id`，写入 `/rustfs-transfer/disk_info.json`。
- SN 不作为业务主身份；业务判断以 `disk_id` 为主，SN 只作为辅助校验和异常提示。
- 如果 SN 为空、变化或重复，前端提示人工确认，不自动当作新盘清理或写入。
