# RustFS 离线运输盘同步技术架构与技术选型

本文档定义系统技术架构、模块职责、运行边界和技术选型。需求、协议字段、状态机和数据库结构分别以以下文档为准：

- [需求文档.md](需求文档.md)
- [开发协议契约.md](开发协议契约.md)
- [数据库设计.md](数据库设计.md)

## 1. 架构原则

- 系统采用中控端、边缘端、运输硬盘三方协作模型。
- 边缘端负责从本地 RustFS 导出数据；中控端负责运输盘注册、初始化、导入、去重和复用控制。
- 在线交互只用于鉴权、硬盘校验、密钥领取和只读查询；对象数据通过运输硬盘离线交接。
- WebSocket 只用于后端向本端前端推送实时状态，不用于边缘端和中控端之间的数据同步。
- 中控端数据库是运输盘注册、边缘站点、密钥、导入任务和对象账本的权威库。
- 边缘端数据库是本地扫描、导出任务、对象状态和运输盘运行状态账本。
- 运输盘生命周期状态以盘内 `disk_info.json.status.code` 为准。
- 运行态、任务态、对象态和启用状态必须使用明确字段名，不得在 API、WebSocket 或 manifest 中使用裸 `status` 混用语义。

## 2. 总体架构

```text
边缘端前端
  <-> 边缘端后端
      <-> 边缘端 PostgreSQL
      <-> 边缘 RustFS S3 API
      <-> Linux udev / mount / ext4
      <-> 运输硬盘

运输硬盘
  /rustfs-transfer/disk_info.json
  /rustfs-transfer/manifests/export_manifest.json
  /rustfs-transfer/manifests/export_manifest.sha256
  /rustfs-transfer/data/
  /rustfs-transfer/meta/
  /rustfs-transfer/logs/
  /rustfs-transfer/quarantine/partial/

中控端前端
  <-> 中控端后端
      <-> 中控端 PostgreSQL
      <-> 中控 RustFS S3 API
      <-> Linux udev / mount / ext4
      <-> 运输硬盘

边缘端后端
  -> 中控端 HTTP API
```

## 3. 后端技术选型

| 类型 | 选型 |
|---|---|
| 开发语言 | Rust |
| 异步运行时 | Tokio |
| HTTP / WebSocket | axum |
| 数据库访问 | sqlx + 显式 SQL |
| 数据库 | PostgreSQL |
| S3 访问 | S3 兼容 SDK，优先使用 `aws-sdk-s3` |
| 序列化 | serde / serde_json |
| 配置 | TOML 配置文件 + 环境变量覆盖 |
| 日志追踪 | tracing / tracing-subscriber / tracing-appender |
| 加密 | AES-256-GCM |
| 校验 | SHA256 |
| ID 与时间 | uuid / chrono |
| 错误处理 | thiserror / anyhow |

约束：

- 不引入 ORM。
- 不引入复杂任务队列或额外消息中间件。
- 数据库迁移使用 `sqlx migrate`。
- 后端服务作为 Linux systemd 常驻服务运行。

## 4. 中控端职责

中控端后端负责：

- 注册运输盘，生成并写入稳定 `disk_id`。
- 初始化和重新初始化运输盘。
- 维护边缘站点、鉴权密钥、运输盘启用状态。
- 生成中控签名密钥和运输盘数据加密密钥。
- 提供边缘端 HTTP HMAC 鉴权接口。
- 校验运输盘是否允许边缘端使用。
- 向通过校验的边缘端发放本次导出使用的 `disk_data_key`。
- 识别 `SEALED` 运输盘并创建导入任务。
- 校验 `disk_info.json`、manifest、密文校验值和明文校验值。
- 解密对象并上传到中控 RustFS。
- 根据 `object_ledger` 做幂等去重。
- 处理跨盘分块对象的到齐、校验、合并和入账。
- 导入完成后写入 `IMPORTED`，再执行清理和重新初始化。
- 通过 WebSocket 向中控端前端推送实时状态。

中控端不得：

- 因清理或重新初始化失败回滚已完成导入任务。
- 将 `CLEANING`、`REINITIALIZING` 写入盘内生命周期状态。
- 对同一 `disk_id + seal_id` 并发启动多个活动导入任务。

## 5. 边缘端职责

边缘端后端负责：

- 识别插入的运输盘并读取盘内协议文件。
- 通过中控端 HTTP API 校验边缘端身份和运输盘授权状态。
- 领取本次运输盘生命周期内的数据加密密钥。
- 扫描本地 RustFS 全部 bucket。
- 通过对象快照和 HEAD 结果判断对象稳定性。
- 过滤正在上传、发生变化或本轮不允许导出的对象。
- 使用 PostgreSQL 行级锁分配对象或分块到运输盘。
- 每块运输盘启动独立 DiskWorker 执行流式导出。
- 使用 AES-256-GCM 加密写入 `.partial` 临时文件。
- 完成校验、`fsync` 和原子重命名后写入 metadata 与 manifest。
- 封盘并写入 `SEALED` 状态。
- 通过 WebSocket 向边缘端前端推送实时状态。

边缘端不得：

- 删除、修改或覆盖 RustFS 源对象。
- 自动清理未导入封存数据。
- 依赖内存锁保证多盘对象唯一分配。
- 将本地 `export_object.status` 写为 `IMPORTED`。
- 保存明文 `disk_data_key` 到数据库或运输盘。

## 6. 运输盘协议

运输盘协议根目录固定为：

```text
/rustfs-transfer/
```

目录约束：

| 路径 | 内容 |
|---|---|
| `disk_info.json` | 运输盘身份、协议版本、生命周期状态、中控签名、密钥编号、封盘信息 |
| `manifests/export_manifest.json` | 有效导出对象和分块清单 |
| `manifests/export_manifest.sha256` | manifest 校验值 |
| `data/` | AES-256-GCM 密文对象或密文分块 |
| `meta/` | 对象 metadata sidecar |
| `logs/` | 本次导出或导入日志摘要 |
| `quarantine/partial/` | 未完成 `.partial` 临时文件隔离区 |

写盘规则：

- 对象数据、metadata、manifest 和 `disk_info.json` 必须采用临时文件、`fsync`、原子重命名。
- `.partial` 只表示未完成对象，不得进入有效 manifest。
- 恢复检查发现 `.partial` 残留时，必须删除或隔离；处理失败不得封盘或导入。
- manifest 中所有相对路径必须位于 `/rustfs-transfer/` 下，不得以 `/` 开头，不得包含 `..`。

## 7. 状态模型

运输盘生命周期状态只写入 `disk_info.json.status.code`：

```text
UNREGISTERED
REGISTERED
INITIALIZED
EDGE_COPYING
SEALED
CENTER_IMPORTING
IMPORTED
ERROR
```

运输盘运行状态只写入 `disk_runtime.status`：

```text
DETECTED
CHECKING
READY
COPYING
CLEANING
REINITIALIZING
DONE
REJECTED
REMOVED
ERROR
```

导出对象状态只写入 `export_object.status`：

```text
PENDING
ASSIGNED
COPYING
EXPORTED
FAILED
SOURCE_CHANGED
SKIPPED
```

密钥状态只写入 `data_key.status`：

```text
ACTIVE
ISSUED
SEALED_READONLY
RETIRED
REVOKED
```

字段命名约束：

- 盘内生命周期：`status_code` 或 `disk_status_code`。
- 运输盘启用状态：`disk_enabled` 或 `enabled`。
- 边缘站点状态：`edge_status`。
- 运输盘运行态：`runtime_status`。
- 导出任务状态：`export_job_status`。
- 导入任务状态：`import_job_status`。
- 对象状态：`object_status`。

## 8. HTTP API 边界

边缘端调用中控端 HTTP API，主要用于：

- `POST /api/edge/auth`：校验边缘站点身份。
- `POST /api/disk/verify`：校验运输盘注册、启用和生命周期状态。
- `POST /api/disk/export-key`：领取本次运输盘数据加密密钥。
- `GET /api/disk/{disk_id}`：查询运输盘注册信息。
- 对象导入账本只读查询接口：用于边缘端优化跳过，不能作为边缘端权威判断。

鉴权约束：

- 所有边缘端调用中控端 API 必须使用 HTTP HMAC 签名。
- 鉴权 Header 必须包含 `X-Edge-Code`、`X-Auth-Key-Id`、`X-Timestamp`、`X-Nonce`、`X-Body-SHA256`、`X-Signature`。
- `X-Signature` 使用 `edge_auth_secret` 对规范化签名串执行 HMAC-SHA256。
- `edge_auth_secret` 只用于 HTTP API 鉴权，不用于文件加密。
- nonce 防重放使用中控端进程内 TTL 缓存，不新增数据库表。

## 9. WebSocket 边界

WebSocket 只连接本端后端和本端前端：

```text
边缘端后端 <-> 边缘端前端
中控端后端 <-> 中控端前端
```

推送内容：

- 硬盘插入、拔出、校验、拒绝和可用状态。
- RustFS 扫描状态。
- 导出和导入任务进度。
- 多盘并行时每块盘独立进度。
- 当前对象、剩余字节数、速度和异常原因。
- 是否可拔盘、是否可复用。

实时进度来源：

- 运行中高频进度来自内存 `ProgressAggregator`。
- WebSocket Publisher 每 1 秒读取内存快照推送。
- 数据库只保存任务阶段、对象状态变更、盘级状态、低频 checkpoint 和最终结果。
- WebSocket 高频推送不得每秒扫描或聚合 `export_job`、`export_object`、`disk_runtime`、`import_job` 或 `object_ledger`。

## 10. 数据库架构

中控端 PostgreSQL 表：

| 表名 | 职责 |
|---|---|
| `disk_list` | 运输盘注册和启用状态 |
| `edge_site` | 边缘站点、鉴权密钥、站点状态 |
| `signature_key` | 中控协议签名密钥 |
| `data_key` | 运输盘数据加密密钥 |
| `import_job` | 导入任务和低频 checkpoint |
| `chunk_import_group` | 跨盘分块对象聚合状态 |
| `chunk_import_part` | 跨盘分块明细 |
| `object_ledger` | 已导入对象账本和全局去重 |

边缘端 PostgreSQL 表：

| 表名 | 职责 |
|---|---|
| `local_object_snapshot` | RustFS 对象扫描快照 |
| `export_job` | 导出任务和低频 checkpoint |
| `export_object` | 对象分配、拷贝状态、分块状态 |
| `disk_runtime` | 运输盘运行状态、容量和错误 |

数据库约束：

- 所有时间字段保存 UTC。
- 多盘对象分配必须使用 PostgreSQL 事务、`SELECT ... FOR UPDATE SKIP LOCKED` 和 `UPDATE ... RETURNING`。
- 普通对象唯一性以 `export_job_id + bucket + object_key + etag + size_bytes + last_modified` 控制。
- 分块对象唯一性以 `chunk_group_id + chunk_index` 控制。
- AES-GCM nonce 必须保证同一 `data_key_id + nonce` 唯一。
- 导入任务并发控制以 `disk_id + seal_id` 为单位。
- 中控去重以 `edge_code + source_bucket + source_key + source_etag + source_size_bytes + source_last_modified` 为对象身份。

## 11. 加密和校验

落盘数据统一使用 AES-256-GCM。

密钥职责：

- `edge_auth_secret`：HTTP API 鉴权密钥。
- `center_key_id`：中控协议签名密钥编号。
- `data_key_id`：运输盘数据加密密钥编号。
- `disk_data_key`：AES-256-GCM 明文数据密钥，只能在边缘端内存中用于本次导出，在中控端用于导入解密。

密钥生命周期：

```text
ACTIVE
-> ISSUED
-> SEALED_READONLY
-> RETIRED
```

约束：

- 运输盘和边缘端数据库不得保存明文 `disk_data_key`。
- `disk_data_key` 不按时间过期，生命周期跟随运输盘本次导出、封盘、导入和重新初始化。
- 运输盘封盘后，中控端不得再发放该 `data_key_id` 给边缘端继续写入。
- 导入完成并重新初始化成功后，旧密钥进入 `RETIRED`。
- `REVOKED` 密钥默认不得自动解密历史数据。

校验顺序：

```text
校验 disk_info.json 签名
-> 校验 manifest SHA256
-> 校验 manifest 字段和分块连续性
-> 校验密文 SHA256
-> AES-GCM tag 认证和解密
-> 校验明文 SHA256
-> 上传中控 RustFS
-> 写入 object_ledger
```

## 12. 多盘并行和跨盘分块

边缘端导出模型：

```text
Scanner
-> Planner
-> PostgreSQL 分配锁
-> 每盘一个 DiskWorker
-> ProgressAggregator
-> WebSocket Publisher
```

对象分配规则：

- 多个 DiskWorker 并发抢占对象时，必须在同一事务中完成锁定和分配。
- Worker 只能处理 `UPDATE ... RETURNING` 返回的对象或分块。
- 单个事务分配对象总大小不得超过当前运输盘 `object_budget_bytes`。
- 运输盘空间不足只停止该盘继续分配，不影响其他盘继续导出。
- 已完整写入并校验通过的对象不得因后续单个对象写满而判定损坏。

容量预算：

- `reserve_bytes = max(1 GiB, min(8 GiB, free_bytes * 2%))`。
- `object_budget_bytes = free_bytes - reserve_bytes - estimated_manifest_bytes - estimated_metadata_bytes - estimated_log_bytes - encryption_overhead_bytes`。
- 调度对象或分块只能使用 `object_budget_bytes`。

跨盘分块规则：

- 单个对象大于单块运输盘可用容量时按分块导出。
- 默认分块大小为 `10 GiB`，即 `10,737,418,240 bytes`。
- 除最后一块外，每个分块大小必须等于 `10 GiB`。
- `chunk_total` 最大为 `1,000,000`。
- 同一 `chunk_group_id` 下 `chunk_index` 必须从 0 连续到 `chunk_total - 1`。
- 中控端必须等同一 `chunk_group_id` 全部分块到齐、校验通过、合并上传成功并写入 `object_ledger` 后，才视为源对象导入完成。

## 13. RustFS 访问

边缘端 RustFS：

- 访问范围为全部 bucket。
- 允许 `List`、`HEAD`、`GET`。
- 禁止删除、覆盖或修改源对象及 metadata。
- 导出前后必须通过对象大小、ETag、last_modified 等信息判断源对象是否变化。

中控端 RustFS：

- 按 `archive-{edge_code}` 创建或复用归档 bucket。
- 归档 key 固定为 `{source_bucket}/{source_object_key}`。
- 上传前查询 `object_ledger` 判断是否已导入。
- 重复对象跳过，不重复写入。

## 14. Linux 和文件系统

运行环境：

- 中控端和边缘端均部署在 Linux。
- 服务使用 systemd 托管。
- 运输盘热插拔使用 udev 触发。
- 服务启动时必须主动扫描已存在运输盘。

文件系统约束：

- 运输盘文件系统固定为 ext4。
- 运行时检测到非 ext4 必须拒绝进入任务池，并记录 `FILESYSTEM_UNSUPPORTED`。
- 边缘端不得格式化、清盘或重新初始化运输盘。
- 中控端负责初始化、导入完成后的清理和重新初始化。

## 17. 日志和观测

日志格式：

- 后端使用结构化 JSON 日志。
- 本机日志按天滚动。
- 默认保留 30 天。
- 运输盘内 `logs/` 只保存本次导出或导入摘要。

关键字段：

- `request_id`
- `job_id`
- `disk_id`
- `seal_id`
- `edge_code`
- `bucket`
- `object_key`
- `etag`
- `error_code`

必须覆盖：

- 硬盘识别、挂载、卸载。
- 协议文件读取和校验。
- HTTP 鉴权、硬盘校验、密钥领取。
- RustFS 扫描和稳定性判断。
- 对象分配、导出、加密、校验和封盘。
- manifest 写入和校验。
- 导入、解密、上传和去重。
- 跨盘分块登记、到齐、合并和入账。
- 清理、重新初始化和失败恢复。
