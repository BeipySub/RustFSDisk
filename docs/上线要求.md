# RustFS 离线运输盘同步上线要求：Edge 端自动流程与前后端联调

本文档用于约束 Edge 端上线前必须完成的自动流程、前端展示、后端联动和联调验收。冻结需求、协议、数据库和架构仍以 `docs/v1.0冻结/` 为准；本文只整理上线实施口径，不替代冻结文档。

## 1. 上线目标

Edge 端上线后，现场人员只需要完成一个人工动作：

```text
把中控端已初始化的运输硬盘插入 Edge 服务器
```

插盘之后，Edge 服务必须自动完成识别、校验、扫描、导出、写盘、封盘，并通过本端 WebSocket 实时反馈给 Edge 前端。Edge 前端必须把每一个阶段以可感知、有视觉反馈的方式呈现出来，让现场人员能够明确知道：

- 系统已经识别到硬盘。
- 硬盘正在校验还是已被拒绝。
- 是否已开始扫描 RustFS。
- 是否已自动进入导出任务。
- 每块盘当前进度、速度、当前对象和剩余量。
- 当前是否可以拔盘。
- 失败时失败在哪一步、错误码是什么、是否需要人工处理。

上线体验要求：

- 不要求现场人员点击“开始扫描”或“开始导出”才能进入主流程。
- 前端只做展示和必要的只读查看，不暴露初始化、清理、格式化、导入、取消任务等危险操作入口。
- 后端是自动流程权威，前端不能自行创造状态枚举或本地推断任务已经完成。

## 2. 范围与边界

本次 Edge 端自动流程覆盖：

- Edge 后端 systemd 服务启动后的现有运输盘主动扫描。
- udev 磁盘变化触发后的运输盘重新发现。
- 运输盘 ext4、SN、挂载点和 `disk_info.json` 校验。
- Edge 通过中控 HTTP HMAC API 校验运输盘注册、启用和生命周期。
- Edge 自动扫描本地 RustFS 全部 bucket。
- Edge 自动创建并启动导出任务。
- 多盘并行对象分配和每盘独立 DiskWorker 写盘。
- AES-256-GCM 加密写盘、metadata、manifest 和封盘。
- Edge 前端 Dashboard 全流程视觉展示。
- 页面刷新后通过 HTTP summary 恢复状态，运行中通过 WebSocket 增量更新。

明确不覆盖：

- Edge 端不得初始化、清理、格式化或重新初始化运输盘。
- Edge 端不得导入运输盘数据。
- Edge 端不得删除、覆盖或修改 RustFS 源对象。
- Edge 前端不得展示或传输 `disk_data_key`、`edge_auth_secret`、控制 token、nonce、tag 或签名密钥。
- Edge 与 Center 之间不得使用 WebSocket 同步业务数据；在线交互只走 HTTP API，对象数据只走运输盘。

## 3. 自动流程总览

```text
Edge 服务启动
-> 主动扫描已存在运输盘
-> 监听 udev 磁盘变化
-> 检测到硬盘插入
-> 后端推送 DISK_DETECTED
-> 读取设备、挂载点、SN、容量和文件系统
-> 后端推送 DISK_CHECKING
-> 校验 ext4 和 /rustfs-transfer/disk_info.json
-> 校验 center_signature、协议版本和盘内 status_code
-> 调用 Center HTTP API 校验 edge 授权和 disk 授权
-> 领取本次导出所需 disk_data_key
-> 后端推送 DISK_READY
-> 自动扫描 Edge RustFS
-> 后端推送 SCAN_STARTED / SCAN_PROGRESS / SCAN_DONE
-> 自动创建 export_job 和 export_object
-> 使用 PostgreSQL 事务为每块盘分配对象
-> 后端推送 COPY_STARTED
-> 每块盘启动 DiskWorker 并行写盘
-> 每秒推送 COPY_PROGRESS
-> 写完对象、metadata、manifest、fsync 并原子重命名
-> 封盘写入 disk_info.json.status.code = SEALED
-> 后端推送 SEAL_DONE
-> 前端展示“封盘完成，可拔盘送往中控端”
```

## 4. 后端自动流程要求

### 4.1 服务启动扫描

Edge 后端启动时必须主动扫描配置允许的运输盘挂载根目录和当前已挂载块设备，不能只依赖 udev 后续事件。

启动扫描必须做到：

- 发现已插入盘时写入或刷新 `disk_runtime` 当前运行态。
- 对同一物理挂载点和当前盘内 `disk_id` 进行重建准入，不能因旧 `disk_runtime` 残留阻断新盘。
- 发现旧任务中间态、`.partial` 残留或盘内 `EDGE_COPYING` 时，先进入恢复检查，不得直接创建新导出任务。
- 每个识别阶段都向 WebSocket 推送可展示事件。

### 4.2 udev 触发规则

udev 只能触发 Edge 后端重新扫描，不得直接执行业务导出、导入、清理或写盘。

要求：

- udev 规则只通知服务或调用只负责 rescan 的轻量入口。
- rescan 由常驻后端进程串行化处理，避免同一块盘并发进入多个自动流程。
- 同一 `disk_id` 的短时间重复插拔事件必须去抖，避免重复创建 export_job。

### 4.3 插盘检测与视觉反馈

后端检测到新硬盘后，必须立即向 Edge 前端推送：

```json
{
  "event_type": "DISK_DETECTED",
  "source": "edge",
  "disk_id": "",
  "disk_status_code": "",
  "runtime_status": "DETECTED",
  "message": "检测到运输硬盘，正在读取设备信息"
}
```

此事件用于驱动前端第一时间出现视觉反馈。即使后续校验失败，也必须先让用户看到“系统已响应插盘动作”。

### 4.4 硬盘准入校验

进入任务池前必须逐项校验：

- 当前文件系统必须是 ext4，否则拒绝并记录 `FILESYSTEM_UNSUPPORTED`。
- 必须能读取 `/rustfs-transfer/disk_info.json`。
- 协议版本必须兼容，否则拒绝并记录 `PROTOCOL_VERSION_UNSUPPORTED`。
- `disk_info.json.status.code` 必须是 `INITIALIZED`，否则拒绝 Edge 写入。
- 盘内 `center_signature` 必须通过校验。
- `.partial` 残留数量必须为 0；如存在残留，先进入恢复检查。
- 必须通过中控 `POST /api/disk/verify` 校验运输盘已注册、已启用、允许当前 Edge 使用。
- 必须通过中控 `POST /api/disk/export-key` 领取本次导出密钥；未领取成功不得开始加密写盘。

拒绝时必须推送 `DISK_REJECTED` 或 `ERROR`，并携带 `last_error_code` 和用户可读 `message`。

### 4.5 自动扫描 RustFS

硬盘进入 `READY` 后，Edge 后端必须自动扫描本地 RustFS。

扫描要求：

- RustFS 全量扫描最多每天执行一次；24 小时内已有成功扫描结果时，自动流程必须复用最近一次成功扫描快照，不得因为重复插盘或重复 udev 事件反复扫描 RustFS。
- 扫描全部 bucket。
- 使用 S3 `List`、`HEAD`、`GET` 的只读能力。
- 通过对象大小、ETag、last_modified 判断对象稳定性；只有上传完成且两次 HEAD 身份一致的对象才能计入稳定对象和待导出容量。
- RustFS 正在上传、正在覆盖或扫描期间发生变化的对象不得计入稳定对象统计，不得进入 `PENDING` 导出队列；本轮只能记录为 `SOURCE_CHANGED` 或不稳定对象。
- 对扫描过程推送 `SCAN_STARTED`、`SCAN_PROGRESS`、`SCAN_DONE`。
- 扫描完成后写入 `local_object_snapshot` 和扫描运行记录；自动创建导出任务时只能使用最近一次成功扫描窗口内 `stable_status = STABLE` 的快照。

扫描期间前端必须能看到 bucket 数、已扫描对象数、稳定对象数、跳过对象数和稳定对象累计容量。24 小时内复用扫描结果时，前端必须明确展示“复用今日扫描结果”或等价提示。

### 4.6 自动创建和启动导出任务

扫描完成且存在可导出对象时，Edge 后端必须自动创建并启动导出任务。

要求：

- `export_job_id` 由后端生成。
- `export_job_status` 从创建、分配、拷贝、封盘到失败全程可追踪。
- `export_object.status` 仅在数据库内部使用；对外统一序列化为 `object_status`。
- Edge 本地对象状态不得包含 `IMPORTED`。
- 多盘并行分配必须使用 PostgreSQL 事务、`SELECT ... FOR UPDATE SKIP LOCKED` 和 `UPDATE ... RETURNING`。
- Worker 只能写入事务 `RETURNING` 返回的对象或分块。
- 容量不足只停止该盘继续分配，不影响其他盘继续导出。

### 4.7 写盘、封盘和可拔盘

DiskWorker 写盘必须遵守：

- 对象数据流式读取、流式 AES-256-GCM 加密。
- 先写 `.partial` 临时文件。
- 完成密文 SHA256、metadata、manifest 条目校验后，`fsync` 并原子重命名。
- `.partial` 不得进入有效 manifest。
- metadata、manifest、`disk_info.json` 均必须使用临时文件、`fsync` 和原子重命名。
- 封盘成功后才能写入 `disk_info.json.status.code = SEALED`。

封盘完成后必须推送：

```json
{
  "event_type": "SEAL_DONE",
  "source": "edge",
  "disk_status_code": "SEALED",
  "runtime_status": "DONE",
  "export_job_status": "SEALED",
  "message": "封盘完成，可以拔盘送往中控端导入"
}
```

前端只有收到 `SEAL_DONE` 或 HTTP summary 中确认 `disk_status_code = SEALED` 且 `runtime_status = DONE` 时，才能展示“可拔盘”。

## 5. 前端展示要求

Edge 前端主页面必须使用 `DashboardView`，首屏直接展示运行态，不做营销页或说明页。

### 5.1 插盘即时反馈

插盘后一旦收到 `DISK_DETECTED`，前端必须立即出现明显视觉反馈：

- 新增一块运输盘的进度卡或时间线节点。
- 使用“检测到硬盘”的视觉状态，不能等扫描完成后才出现。
- 展示设备挂载点、SN、容量、`disk_id` 可用则展示。
- 用加载动效表现正在检查。

推荐状态文案：

```text
检测到运输硬盘
正在读取协议文件和授权信息
```

### 5.2 全流程时间线

每块运输盘必须展示独立时间线：

```text
已检测
-> 校验中
-> 已授权
-> 扫描 RustFS
-> 分配对象
-> 写盘中
-> 生成清单
-> 封盘完成
-> 可拔盘
```

失败时，时间线停在失败节点，并展示标准错误码。

### 5.3 多盘并行展示

多盘场景下，前端必须以 WebSocket `disks[]` 作为每块盘独立进度来源。

每块盘至少展示：

- `disk_id`
- `disk_status_code`
- `runtime_status`
- `export_job_status`
- `done_bytes / total_bytes`
- `remaining_bytes`
- `free_bytes`
- `speed_bytes_per_sec`
- `object_done / object_total`
- 当前对象 `current_object.display_name`
- 当前对象 `current_object.done_bytes / size_bytes`
- `last_error_code`
- `message`

全局区域至少展示：

- 总进度。
- 总速度。
- 总剩余字节数。
- 当前活跃盘数量。
- 已完成盘数量。
- 异常盘数量。

### 5.4 页面刷新恢复

页面刷新后，前端必须先调用只读 HTTP summary 恢复当前状态，再连接 WebSocket。

推荐顺序：

```text
GET /api/edge/dashboard/summary
-> 渲染当前盘列表、任务摘要和最近错误
-> 连接 GET /ws/edge/copy-progress
-> 使用 WebSocket 事件覆盖运行中快照
```

HTTP summary 用于首次加载和断线恢复；WebSocket 用于运行中实时变化。前端不得每秒轮询数据库聚合进度。

### 5.5 操作入口限制

Edge 前端允许：

- 查看 Dashboard。
- 查看导出记录列表。
- 查看导出任务详情。
- 查看错误原因和建议处理动作。

Edge 前端禁止：

- 初始化运输盘。
- 清理运输盘。
- 格式化运输盘。
- 重新初始化运输盘。
- 导入运输盘。
- 取消正在写盘的底层 DiskWorker。
- 展示或发送任何密钥、token、nonce、tag。

## 6. 前后端联调契约

### 6.1 HTTP 接口

浏览器只读接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/edge/dashboard/summary` | Dashboard 首次加载和刷新恢复 |
| `GET` | `/api/edge/dashboard/export-jobs` | 导出记录列表 |
| `GET` | `/api/edge/dashboard/export-jobs/{export_job_id}` | 导出任务详情 |

受控运维接口：

| 方法 | 路径 | 用途 | 要求 |
|---|---|---|---|
| `GET` | `/api/edge/summary` | 运维 summary | 需要 `X-Edge-Control-Token` |
| `POST` | `/api/edge/rescan` | 人工触发重新扫描设备 | 需要 `X-Edge-Control-Token` |
| `POST` | `/api/edge/scan` | 人工触发 RustFS 扫描 | 需要 `X-Edge-Control-Token` |
| `POST` | `/api/edge/export-jobs` | 人工创建导出任务 | 需要 `X-Edge-Control-Token` |
| `POST` | `/api/edge/export-jobs/{export_job_id}/start` | 人工启动导出任务 | 需要 `X-Edge-Control-Token` |

上线后的默认主流程必须由后端自动触发；受控运维接口只用于排障和演示补救，不作为现场常规操作。

### 6.2 WebSocket 接口

Edge 前端连接：

```text
GET /ws/edge/copy-progress
```

兼容路径：

```text
GET /ws/edge/progress
```

事件类型必须覆盖：

- `DISK_DETECTED`
- `DISK_CHECKING`
- `DISK_READY`
- `DISK_REJECTED`
- `DISK_REMOVED`
- `SCAN_STARTED`
- `SCAN_PROGRESS`
- `SCAN_DONE`
- `COPY_STARTED`
- `COPY_PROGRESS`
- `COPY_DONE`
- `SEAL_DONE`
- `ERROR`

运行中高频进度必须来自内存 `ProgressAggregator` 快照，不得每秒扫描 `export_job`、`export_object` 或 `disk_runtime` 聚合实时进度。

### 6.3 字段命名

HTTP 和 WebSocket payload 中必须使用明确语义字段：

| 含义 | 字段 |
|---|---|
| 运输盘生命周期 | `disk_status_code` 或 `status_code` |
| 运输盘运行态 | `runtime_status` |
| 导出任务状态 | `export_job_status` |
| 对象状态 | `object_status` |
| 运输盘启用状态 | `disk_enabled` 或 `enabled` |
| 边缘站点状态 | `edge_status` |

| `DISK_REJECTED` | 拒绝态 | 当前硬盘不可用于 Edge 导出 |
| `ERROR` | 错误态 | 按错误码处理后重试 |
| `DISK_REMOVED` | 移除态 | 已检测到硬盘拔出 |

## 8. 异常处理展示

前端必须展示标准错误码和用户可读说明。

重点错误：

| 错误码 | 前端提示 |
|---|---|
| `FILESYSTEM_UNSUPPORTED` | 当前硬盘不是 ext4，不能进入导出任务 |
| `PROTOCOL_VERSION_UNSUPPORTED` | 运输盘协议版本不兼容 |
| `UNAUTHORIZED` | Edge 或运输盘授权失败 |
| `RECOVERY_REQUIRED` | 检测到中间态，需要恢复检查 |
| `PARTIAL_FILE_FOUND` | 发现未完成临时文件，不能继续封盘 |
| `PARTIAL_CLEAN_FAILED` | 临时文件清理或隔离失败，需要人工处理 |
| `DISK_REMOVED` | 写盘过程中硬盘被拔出，任务已停止 |
| `DISK_FULL` | 当前硬盘空间不足，已停止该盘继续分配 |
| `INSUFFICIENT_SPACE` | 当前硬盘可分配空间不足 |
| `SOURCE_CHANGED` | 源对象发生变化，本轮跳过该对象 |
| `CHECKSUM_MISMATCH` | 校验值不一致 |
| `MANIFEST_INVALID` | manifest 非法或字段不一致 |

异常状态下，前端不得显示“可拔盘送中控导入”，除非后端明确给出封盘完成事件。

## 9. 安全与数据要求

上线前必须确认：

- Edge 后端不保存明文 `disk_data_key` 到数据库或运输盘。
- Edge 前端响应中不包含 `disk_data_key`、`edge_auth_secret`、控制 token、nonce、tag、`data_key_id` 等敏感信息。
- Edge 后端只读访问源 RustFS，不执行删除、覆盖或修改。
- Edge 后端在中控不可达但已完成硬盘校验并已领取本次 `disk_data_key` 时，可以继续本地导出；如果尚未领取密钥，不得开始新的加密导出。
- Edge 封盘后不得再次领取同一 `data_key_id` 继续写入。
- Edge 不得把中控导入结果写回本地 `export_object.status`。

## 10. 联调步骤

### 10.1 后端联调

1. 启动 Edge 后端 systemd 服务。
2. 确认 `/healthz` 和 `/readyz` 返回 200。
3. 插入中控已初始化的 ext4 运输盘。
4. 确认后端日志出现磁盘检测、协议校验、中控 verify、export-key、扫描、创建导出任务、启动 DiskWorker、封盘事件。
5. 确认 Edge 数据库中 `disk_runtime` 当前盘进入正确运行态。
6. 确认 `export_job` 最终进入 `SEALED`。
7. 确认 `export_object` 只有 `EXPORTED`、`FAILED`、`SOURCE_CHANGED`、`SKIPPED` 等 Edge 合法对象态，不出现 `IMPORTED`。
8. 确认盘内 `.partial=0`。
9. 确认盘内 `disk_info.json.status.code = SEALED`。
10. 确认 manifest、data、meta 文件数量与导出对象一致。

### 10.2 前端联调

1. 打开 Edge Dashboard。
2. 页面首次加载调用 `/api/edge/dashboard/summary` 并渲染当前盘列表。
3. 连接 `/ws/edge/copy-progress`。
4. 插盘后 1 秒内出现“检测到运输硬盘”的视觉反馈。
5. 校验阶段展示 `CHECKING`，失败时展示错误码。
6. 授权成功后展示 `READY` 并自动进入扫描。
7. 扫描期间展示对象数和容量增长。
8. 导出期间展示全局进度和每盘独立进度。
9. 当前对象变化时，前端立即更新文件名、对象进度和速度。
10. WebSocket 断开后，页面能通过 HTTP summary 恢复状态，并在重连后继续更新。
11. 封盘完成后展示“可以拔盘送往中控端导入”。

### 10.3 自动流程联调

必须跑通以下主路径：

```text
Center 初始化运输盘
-> 运输盘插入 Edge
-> Edge 前端出现插盘反馈
-> Edge 后端自动校验
-> Edge 后端自动扫描 RustFS
-> Edge 后端自动创建并启动导出
-> Edge 前端展示 COPY_PROGRESS
-> Edge 后端封盘
-> Edge 前端展示 SEAL_DONE 和可拔盘
```

## 11. 上线验收标准

Edge 自动流程验收：

- 插盘后无需人工点击，后端自动流转到扫描和导出。
- 插盘后前端必须有即时视觉反馈。
- 所有关键阶段均可在前端看到。
- 多盘并行时每块盘有独立进度。
- 页面刷新后状态不丢失。
- WebSocket 断开后可恢复。
- 封盘前不得提示可拔盘。
- 封盘后必须明确提示可拔盘。
- 任意失败必须展示标准错误码。
- 非 ext4、未注册、未授权、协议不兼容、`.partial` 残留必须被拒绝。
- Edge 不暴露危险操作入口。
- Edge 不暴露敏感密钥或 token。

联调通过判定：

```text
一块 Center 已初始化运输盘插入 Edge 后，
Edge Dashboard 能从 DISK_DETECTED 连续展示到 SEAL_DONE，
盘内最终为 SEALED，
导出对象和 manifest 校验一致，
期间无需人工触发 scan/export。
```

## 13. Edge 自动流程部署开关与回滚

默认部署必须保持自动流程关闭：

```toml
[auto_export]
enabled = false
start_on_ready = false
min_ready_disk_count = 1
cooldown_seconds = 60
```

启用前检查：

1. 确认 `rustfs-transfer-edge.service` 使用 `ExecStart=/opt/rustfs-transfer/rustfs-transfer-edge`，并加载 `/etc/rustfs-transfer/edge.toml` 与 `/etc/rustfs-transfer/edge.env`。
2. 确认 `rustfs-transfer-disk-rescan@.service` 只执行 `/opt/rustfs-transfer/bin/rustfs-transfer-rescan --device /dev/%I --trigger udev`。
3. 确认 `99-rustfs-transfer-disk.rules` 只拉起 rescan 模板，不直接调用 scan、export、import、cleanup、reinitialize、mkfs 或 format。
4. 在目标 Edge 上先运行部署静态检查，再由授权人决定是否开启自动流程。

灰度启用步骤：

```text
RUSTFS_TRANSFER__AUTO_EXPORT__ENABLED=true
RUSTFS_TRANSFER__AUTO_EXPORT__START_ON_READY=true
RUSTFS_TRANSFER__AUTO_EXPORT__MIN_READY_DISK_COUNT=1
RUSTFS_TRANSFER__AUTO_EXPORT__COOLDOWN_SECONDS=60
```

写入 `/etc/rustfs-transfer/edge.env` 后，重启 `rustfs-transfer-edge`。启用后仍必须经过 ext4、`disk_info.json.status.code=INITIALIZED`、Center verify/export-key、`.partial` 恢复检查和既有活动任务门禁；udev 只负责触发 rescan。

回滚步骤：

```text
RUSTFS_TRANSFER__AUTO_EXPORT__ENABLED=false
RUSTFS_TRANSFER__AUTO_EXPORT__START_ON_READY=false
```

写回 `/etc/rustfs-transfer/edge.env` 并重启 `rustfs-transfer-edge` 后，插盘只刷新盘态，不自动 scan/export。人工受控 API 模式保持可用：`POST /api/edge/scan`、`POST /api/edge/export-jobs`、`POST /api/edge/export-jobs/{export_job_id}/start` 仍需 `X-Edge-Control-Token`。

排障核查：

- `auto_export.enabled=false` 或 `start_on_ready=false`：只应看到磁盘识别和 READY，不应创建新 `export_job`。
- 已有 `PENDING`、`SCANNING`、`COPYING`、`SEALING` 等活动导出任务：不得创建第二个自动任务。
- Center verify/export-key 失败：不得开始加密写盘，日志必须保留标准错误码。
- 重复 udev 事件：应受 `cooldown_seconds` 和活动任务门禁保护，不得重复全量扫描或重复建任务。
