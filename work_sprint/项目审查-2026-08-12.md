## 4. 代码层残留风险

### P0：真实端到端验收缺失

当前单元测试和局部集成测试通过，但仍未看到真实环境主闭环验收记录：

```text
Center 初始化盘
-> Edge 插盘准入
-> RustFS 扫描
-> 自动创建/启动导出
-> AES-GCM 写盘封盘
-> Center 导入去重
-> 清理重新初始化
-> 双端 Dashboard 真实展示
```

这不是文档小问题，是上线判断的最大缺口。

### P0：前端构建环境不可复现

双端前端当前无法执行 `vue-tsc`，因此不能确认 `TASK-S1-WEB-EDGE-PROD-001` 和 `TASK-S1-WEB-EDGE-TIMELINE-001` 的最新代码在当前环境仍可构建。

### P1：Edge 封盘后删除 `disk_runtime` 可能影响可视化恢复

`crates/edge-backend/src/export_runtime.rs` 中生产路径定义：

```text
DELETE FROM disk_runtime WHERE disk_id = $1
```

并在 DiskWorker 成功封盘后调用清理运行态。这个设计保护“导出历史不被恢复路径误判”，但会让 HTTP summary 失去该盘的运行态行。若前端依赖 summary 展示“SEALED / 可拔盘”，需要确认 WS `SEAL_DONE`、导出记录和 summary 的组合足够支撑刷新后恢复。

### P1：跨盘分块仍偏 MVP

Center `ImportWorker` 已能登记分块、检测缺块不入账，并在同一进程可见全部 `chunk_parts` 后合并上传。但实现中合并使用内存 `Vec` 聚合完整明文，且真实跨盘、跨任务、跨进程恢复能力没有看到完整验收。冻结需求要求大对象跨多盘分块导出/导入，当前更接近“字段、登记、缺块防护和局部合并”。

### P1：自动导出活动任务判断未包含 `SEALING`

`crates/edge-backend/src/auto_export.rs` 的活动任务集合为 `PENDING / SCANNING / COPYING`，不包含 `SEALING`。如果 `export_job.status = SEALING` 的窗口存在，自动编排可能误判没有活动任务。需要确认当前生产路径是否实际写入 `SEALING`；若写入，应补齐。

### P2：AGENTS.md 文件编码异常

根目录 `AGENTS.md` 用默认读取出现乱码，但用户消息中提供了正确内容。后续代理若只依赖本地文件默认编码读取，可能误解规则。建议确认文件真实编码并统一以 UTF-8 保存；注意这不是冻结文档目录，允许修复，但需谨慎。
