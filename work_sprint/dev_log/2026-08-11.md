### TASK-S1-EDGE-HOTFIX-003：Edge disk_runtime 可重建准入修补

- 范围：仅代码、测试、TASKS 与本日志记录；未部署、未调用真实 API/VM，未操作硬盘、数据库或生产 SQL，未修改冻结文档。
- 架构口径：用户明确 `disk_runtime` 仅代表“当前插入、当前可运行”的临时运行态；新盘发现、scan、创建/启动导出任务不得以旧 `disk_runtime.disk_id` 与盘内 `disk_info.disk_id` 匹配作为准入条件。
- 修补内容：
  - `crates/edge-backend/src/server.rs`、`crates/edge-backend/src/rescan.rs`：受控 scan、创建导出任务、启动导出任务前同步执行一次当前运输盘发现；发现失败则在写任务前拒绝。
  - `crates/edge-backend/src/disk_detection.rs`：当前盘发现成功时，先按当前 `device_path`/`mount_path` 和当前盘 `disk_id` 替换同盘旧 runtime 快照，再写入本次发现结果；旧缓存不参与盘身份选择或拒绝。
  - `crates/edge-backend/src/disk_worker.rs`、`crates/edge-backend/src/export_runtime.rs`：导出成功、manifest 与封盘写入完成后，在同一受控完成流程中删除该盘对应 `disk_runtime`；不删除 `export_job`、`export_object`、manifest 或 seal 历史。
  - `crates/edge-backend/src/control.rs`：控制查询仍只读取当前 runtime 表内 READY 行，不使用物理槽位排序作为盘身份验收门禁。
- 安全边界：
  - 盘内 `disk_info.disk_id` 仍必须经 Center HMAC `/api/disk/verify` 与登记状态校验，且盘内状态必须是 `INITIALIZED`。
  - 非 ext4、缺硬件 SN、`.partial` 残留、`EDGE_COPYING`、Center 签名/登记拒绝仍不得进入 READY。
  - 历史 `export_job`、`export_object`、manifest、seal 和真实导出审计记录不作为新盘准入前置，也不会被本补丁清理。
- 验证结果：
  - `cargo fmt --all -- --check`：通过。
  - `cargo test -p rustfs-transfer-edge`：普通沙箱因 `target/debug/.cargo-build-lock` 权限拒绝未启动；最小权限重跑通过，覆盖旧 runtime 不阻断新盘、封盘成功后 runtime 删除且历史保留、Center 签名拒绝/非 ext4/`.partial` 阻断。
  - `powershell -ExecutionPolicy Bypass -File scripts\check-deploy.ps1`：通过。
  - 真实 Edge VM 尚未部署本补丁；需部署窗口更新 Edge 后先执行只读 rescan/summary 核验，再触发 scan/export。
