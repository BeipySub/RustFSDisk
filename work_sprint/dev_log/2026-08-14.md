## Center/Edge KEY Model Implementation

- Scope: implement the simplified Center-created Edge KEY flow after committing the previous baseline.
- Completed:
  - Center Edge site creation now generates a single `edge_key`, wraps it with the local master key for storage, and returns the plaintext KEY for Edge configuration.
  - Center Edge site list responses now return viewable `edge_key`; database-facing code uses `edge_key_ciphertext`.
  - Added Center Edge site KEY reset API and UI action for redeployment or legacy key recovery.
  - Removed `auth_key_id` from Center HMAC request signing and nonce scope; `edge_code` now identifies the site and `edge_key` signs requests.

  - Edge config now uses `[edge] edge_code` and `edge_key`; legacy `[center]` auth fields and Edge `control_api_token` are removed from delivery config.
  - Edge manual control API routes now return `CONTROL_API_REMOVED`; read-only dashboard routes remain available.
  - Added Center migration `sql/center/0003_edge_site_edge_key.sql` to move the schema to `edge_key_ciphertext` and `key_updated_time`.
  - Added Center migration `sql/center/0004_drop_unused_signature_key.sql` so the unused `signature_key` table is removed consistently across environments.
  - Updated Center Edge management page to create sites without manual key fields and display/copy the Center-generated KEY.
  - Removed the Sync Records page back-to-Dashboard button and restored the Edge management page to the global dark panel styling.
