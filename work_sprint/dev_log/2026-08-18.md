## Edge 历史导出对象去重修复

- 问题：Edge 创建新导出计划时，历史已随 `SEALED` 任务导出的对象版本需要跳过；现有去重条件包含 `last_modified`，同一对象内容版本在 RustFS 返回时间变化时会再次进入导出计划。
- 修改：导出计划和扫描入队的历史去重条件固定为 `bucket + object_key + etag + size_bytes`，`last_modified` 保留入库用于审计，不参与去重命中；新增 `sql/edge/0007_export_dedup_source_version_index.sql` 支撑该查询。
- 修改：Edge Dashboard 的 RustFS 对象总量改为统计最近一次成功扫描窗口内的稳定对象，避免把 `local_object_snapshot` 历史快照累加展示成当前对象总数。
- 验证：`cargo fmt --all -- --check` 通过；`cargo test -p rustfs-transfer-edge` 通过。

## Edge 当前扫描窗口重复快照收口

- 问题：`local_object_snapshot` 是审计历史表，允许跨扫描保留多条快照；但 Planner 未折叠最新成功扫描窗口内的同一对象身份，遇到同一对象出现多条稳定快照且 `last_modified` 不同时，旧唯一索引允许在同一导出任务内生成多条 `export_object`，导致重复拷贝。
- 修改：Planner 固定按 `bucket + object_key + etag + size_bytes` 对最新扫描窗口的稳定快照取最新一条，再过滤历史 `SEALED + EXPORTED` 对象版本。运行期 `ProgressAggregator` 对象总量也改为最近成功扫描窗口内按 `bucket + object_key` 取最新记录，避免 WebSocket 展示历史快照累加值。
- 保留：不删除 `local_object_snapshot` 审计记录；不自动删除或更改已创建的导出任务对象，避免影响正在执行或待恢复的任务。

## Edge Dashboard 导出实时计数修复

- 问题：复制过程的 `global_progress` 会更新，但 `object_inventory` 只在任务开始时初始化；WebSocket 因此持续发送 `exported_count = 0` 和 `exported_bytes = 0`，导致 Dashboard 的“已导出对象/已导出数据量”不随对象完成同步。
- 修改：对象完成的边界固定为对象数据原子落盘、metadata 写入且数据库 `mark_exported` 成功之后。`ProgressAggregator::complete_object` 在该边界递增 `object_inventory.exported_count/exported_bytes`，并限制在当前扫描库存总量以内；重复完成同一当前对象不会重复计数。
- 修改：Dashboard 顶部进度区将原“对象”计数替换为“当前序号”，复制中显示 `第 N / M 个`，全部对象完成后显示 `已完成 M / M`。
- 修改：活动导出期间 Dashboard 的“已导出对象/已导出数据量”直接显示同一 WebSocket `global_progress.object_done/done_bytes`，使对象完成数和复制字节数随事件实时变化；任务结束后恢复显示持久化对象库存统计。
- 验证：`cargo fmt --all -- --check` 通过；`cargo test -p rustfs-transfer-edge` 通过（93 个单测和 3 个集成测试）；`pnpm test:unit` 通过（28 个单测）；`pnpm typecheck` 和 `npm run build` 通过。

## Edge 当前对象快照去冗余

- 问题：`local_object_snapshot` 以纯 INSERT 保存每次扫描结果，未变化对象会跨扫描重复累积；这与冻结数据库设计中“最近一次成功扫描快照”的表用途不一致，并使对象统计和导出编排查询需要额外折叠历史数据。
- 修改：新增 `sql/edge/0008_current_object_snapshot.sql`。迁移先保留每个 `bucket + object_key` 的最新遗留记录、删除旧重复记录，再为当前快照表建立唯一索引；新增 `local_object_scan_stage` 作为单次扫描暂存表。
- 修改：扫描对象先按 `scan_run_id + bucket + object_key` upsert 到暂存表。仅在整次扫描成功后，事务内将暂存快照原子替换为当前快照并清理暂存行；扫描失败仅清理自己的暂存行，不修改上一轮成功快照。
- 修改：导出 Planner、Dashboard 库存统计和运行期进度库存直接查询当前稳定快照，不再按历史扫描窗口过滤或折叠。
- 验证：`cargo fmt --all -- --check` 通过；`cargo test -p rustfs-transfer-edge` 通过（93 个单测和 3 个集成测试）；`git diff --check` 通过。未执行真实数据库迁移：Edge VM 未安装 `psql` 客户端，需通过现有 PostgreSQL 管理工具执行 `0008_current_object_snapshot.sql`。

## Edge Dashboard 复制静态字段和任务计数修复

- 问题：COPY_PROGRESS WebSocket 快照没有携带运输盘 `filesystem_type`，浏览器若先收到实时事件会显示“系统格式：未返回”；封盘后 summary 只读取活动导出任务，导致最近封盘批次的完成对象数和传输字节数无法作为任务最终值保留。
- 修改：进度聚合器在分配阶段一次性读取并缓存磁盘文件系统类型，所有后续 COPY_PROGRESS 快照复用该静态字段，不在高频推送中执行系统命令或查询数据库。
- 修改：summary 在没有活动任务时返回最近一批导出任务；封盘或失败进度快照允许向 WebSocket 发送一次终态事件后再释放内存聚合器。Dashboard 的指标统一为“已完成对象”和“已传输数据量”，始终优先展示当前或最近任务的精确完成数。
- 验证：`cargo fmt --all -- --check` 通过；`cargo test -p rustfs-transfer-edge` 通过（93 个单测和 3 个集成测试）；`pnpm test:unit` 通过（28 个单测）；`pnpm typecheck` 和 `npm run build` 通过；`git diff --check` 通过。

## Edge Dashboard 历史导出库存口径校正

- 问题：扫描与导出概览中的后两项是 Edge 历史累计导出对象和数据量，不能被当前或最近导出任务覆盖；最近任务为零时会错误展示 `0 / 0 B`。
- 修改：该区域固定使用 `object_inventory.exported_count/exported_bytes`，保留页面原有“已导出数量/已导出数据量”文案；当前任务的实时完成数只保留在顶部导出进度和当前对象区域展示。

## Edge 空导出计划不再阻塞后续批次

- 问题：自动导出在扫描到稳定对象后创建导出任务，再由 Planner 执行历史版本去重；当全部对象都已随 `SEALED` 批次导出时，Planner 会得到 0 个候选对象，但原任务仍是 `PENDING`，被后续自动编排视为活动任务而阻塞。
- 修改：Planner 得到 0 个可导出对象时，任务在同一事务内改为 `CANCELLED`、写入结束时间及明确原因。该任务不会写盘，也不再属于活动任务；后续扫描发现真正新增或版本变化对象时可正常创建下一批任务。
- 验证：`cargo fmt --all -- --check` 通过；`cargo test -p rustfs-transfer-edge export_planner::tests` 通过（6 个测试）。Edge VM 已同步源码并由 `cargo watch` 重编译；历史零对象 `PENDING` 任务已仅更新为 `CANCELLED`，未删除任何对象、扫描或盘内数据。

## Edge 复制中系统格式字段保持

- 问题：分配阶段创建的进度对象已缓存 `filesystem_type`，但 Worker 启动时无条件替换该进度对象，导致复制中的 WebSocket 快照丢失 `ext4`，Dashboard 显示“未返回”。
- 修改：Worker 启动时按 `export_job_id` 复用已安装的进度对象，只有没有对应任务时才新建。分配阶段已写入的磁盘、文件系统类型和对象统计会完整进入复制阶段。

## Edge 封盘阶段与历史导出统计校正

- 问题：所有对象字节写完后，仍需完成 metadata、manifest、`fsync` 和盘内状态原子更新；进度事件却继续携带 `COPYING`，使 100% 页面看起来仍在写对象。另一个问题是历史导出统计只按 `bucket + object_key` 合并，当前对象同路径但版本变化时会少算已封盘的新版本。
- 修改：最后一个对象完成后，运行态进度明确切换为 `SEALING`，直到盘内封盘完成才切换为 `SEALED`。历史导出数量和数据量固定以当前稳定快照为基准，按 `bucket + object_key + etag + size_bytes` 确认该当前版本已存在于任意 `SEALED` 导出任务；同路径的新版本不再被旧版本合并掉。
