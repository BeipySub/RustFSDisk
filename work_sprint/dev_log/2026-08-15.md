## 运输盘流式存储整改方案容量预算修订

- 范围：审查 v2 存储整改方案是否覆盖硬盘容量、多盘分配、加密和元数据开销，未修改 `docs/v1.0冻结/`。
- 发现问题：方案已有 PACK/FRAMES 存储模型，但未把冻结协议中的容量预算和多盘分配规则迁移到 v2，存在按源对象 `size_bytes` 分配导致 metadata、manifest、pack index、recovery index、日志和 AES-GCM 元数据无空间落盘的风险。
- 修订内容：
  - 新增“容量预算与多盘分配”章节，固定 `reserve_bytes` 和 `object_budget_bytes` 公式。
  - 新增 `estimated_landing_bytes`，要求 Planner 按预计落盘大小分配，不得按源对象大小或硬盘总容量分配。
  - 固定 PACK 和 FRAMES 的估算参数，覆盖 manifest、metadata、pack index、recovery index、日志、GCM tag、nonce、AAD 和文件系统块对齐预算。
  - 明确空间不足时当前盘停止分配，其他 `READY` 盘继续；写盘 ENOSPC 记 `DISK_FULL`，分配预算不足记 `INSUFFICIENT_SPACE`。
  - 明确 FRAMES 以 frame 为容量分配单元，允许同一对象的 frame 分配到多块运输盘。
  - 修正 FRAMES 跨盘后的数据库模型：`export_object.disk_id` 仅用于 PACK，FRAMES 的目标盘记录在 `export_object_frame.disk_id`。
  - 修正 Center FRAMES 导入流程：先暂存并登记 frame，全部 frame 到齐后按 `export_job_id + object_id` 合并上传，再写入 `object_ledger`。
- 验证方式：使用 `rg` 检查 `estimated_landing_bytes`、`object_budget_bytes`、`INSUFFICIENT_SPACE`、`DISK_FULL`、`frame_total`、`object_frame_import`、`MERGED` 等关键字段和流程已写入方案；未运行编译或测试。

## 运输盘流式存储整改方案前端契约复审

- 范围：复查整改方案和当前 Edge/Center 前端代码，确认破坏性升级不会残留旧通讯字段、兼容别名或错误展示逻辑，未修改 `docs/v1.0冻结/`。
- 发现的问题：
  - 当前 Edge 前端仍存在 `current_object.relative_data_path`、WebSocket `global` 兼容别名、HTTP `records/total_count` 兼容兜底。
  - 当前 Center 同步记录仍展示 `chunk_group_id/ciphertext_sha256`，并基于 `chunk_group_id` 统计“跨盘分块”。
  - 方案中 `PACK` 对象摘要示例曾写为 `frame_total = 1`，与后文 `PACK` 必须为 `frame_total = 0` 冲突。
  - 当前 Center 磁盘进度类型缺少 `free_bytes/reserve_bytes/object_budget_bytes`，破坏性升级后不能继续用 `capacity_bytes/total_bytes` 推导可用空间展示。
- 修订内容：
  - 将 `PACK` 对象摘要示例固定为 `frame_total = 0`，并明确 `frame_total > 0` 只表示 `FRAMES` 对象。
  - 明确 Edge/Center 磁盘列表、任务启动结果和 WebSocket 盘级进度必须输出 `capacity_bytes/free_bytes/reserve_bytes/object_budget_bytes`。
  - 明确删除 WebSocket `global` 别名，Dashboard 汇总事件只使用 `global_progress`。
  - 明确 HTTP 分页响应只使用 `page/page_size/total/items`，删除 `records/total_count` 兼容别名。
  - 明确 Center 同步记录按 `storage_mode` 展示和统计 `PACK/FRAMES`，删除基于 `chunk_group_id` 的统计和标签。
- 代码对照结论：
  - 原代码已经具备容量预算字段、`reserve_bytes/object_budget_bytes` 公式和 `FOR UPDATE SKIP LOCKED` 分配骨架。
  - 原代码的容量分配仍绑定 v1 `Plain/Chunked`、`chunk_*` 和 `chunk_size_bytes` 模型，缺少 v2 `estimated_landing_bytes`、PACK/FRAMES 元数据预算和 `export_object_frame` 跨盘 frame 账本。
- 验证方式：使用 `rg` 对方案文档、开发日志、`web/edge-web/src`、`web/center-web/src`、`crates/edge-backend/src/export_planner.rs` 和 `sql/edge/0001_init_edge.sql` 进行字段对照；本次仍是文档修订，未运行编译或测试。
