# 2026-08-13

## Linux default maximum shared permissions

- Set both Edge and Center process umask to `000` on Linux, so newly created directories default to `0777` and regular files to `0666` without any user or group dependency.
- Added `UMask=0000` to both production systemd units, covering service deployments as well as the application startup guard used by `cargo watch`.

## Edge VM automatic export override correction

- Found that `/etc/rustfs-transfer/edge.env` set `RUSTFS_TRANSFER__AUTO_EXPORT__ENABLED=true`, overriding `enabled = false` in `edge.toml`.
- Updated the effective environment override to `false`; the Edge process must restart once to load it.

## Edge write-before permission regression correction

- Root cause: the all-user permissions change attempted `chmod 0777` from the Edge DiskWorker against existing protocol directories owned by `fustfs-agent`. The `edge` user has write ACL access but is not the owner, so Linux returned `Operation not permitted` before the first write.
- Change: removed runtime directory `chmod` calls from Edge DiskWorker. Existing disk ACLs continue to provide all-user directory access; files created by the worker remain explicitly set to `0666`.

## Edge particle path alignment

- Adjusted the particle path anchors to the visible source rack drive-bay edge and the transport array's left-side transfer port, compensating for transparent image margins.
- Verification: `npm run typecheck` and `npm run build` in `web/edge-web`.

## Transport disk default Linux permissions

- Change: protocol directories are set to `0777` and protocol files to `0666` after creation and atomic rename, preventing the running user or `umask` from tightening later writes.
- VM: `/media/edge` is traversable by all users; the current disk's `rustfs-transfer` tree and default ACL are open to all users.

- 文档规则对齐：
  - `auth_key_id` 只用于边缘端调用中控 HTTP API 鉴权，不得与 `signature_key.key_id` 或 `data_key_id` 混用。
  - `edge_auth_secret` 用于 HMAC-SHA256 请求签名，中控端应加密保存到 `edge_site.auth_secret_ciphertext`，边缘端部署持有同一明文。
  - 边缘站点注册后不支持重置、替换或轮换密钥。
- 变更：

- 修复：udev 或启动检测在硬盘尚未 `READY + INITIALIZED` 时，每秒重检一次，最多 5 次；真正就绪后才进入既有扫描、任务创建、分配和 Worker 流程。
- 边界：`ControlRefresh` 仍只用于页面刷新，不会触发自动导出；已有活动任务门禁与冷却逻辑保持不变。未发现就绪盘的首次检测不消耗冷却时间。
- 验证：`cargo fmt --all -- --check` 通过；`cargo test -p rustfs-transfer-edge udev_rescan_rechecks_until_the_disk_is_ready_before_starting_auto_export` 通过；`cargo test -p rustfs-transfer-edge` 通过（78 个单元测试、3 个集成测试）。

# Center 已插盘展示与一键注册初始化

- 范围：`crates/center-backend/src/lib.rs`、`web/center-web/src/api/centerDashboard.ts`、`web/center-web/src/views/DashboardView.vue`、`web/center-web/src/style.css`。
- 修复：Center Dashboard summary 在数据库盘台账基础上合并 Linux 已挂载 ext4 运输盘；盘内状态通过既有 `read_disk_info_document` 读取，不重新实现协议解析。
- 交互：前端磁盘卡片支持按状态调用既有 `/api/disk/register`、`/api/disk/initialize`、`/api/center/disks/{disk_id}/reinitialize`。新盘一键注册后继续调用既有初始化接口；已封盘/已导入盘只在后端判定可重初始化时显示动作。
- 边界：未改导入、导出、密钥生成、disk_info 写入和重初始化服务内部逻辑；已封盘/已导入但未在 Center 数据库登记的盘不会被当作新盘覆盖初始化。
- 验证：`cargo fmt --all -- --check` 通过；`cargo test -p rustfs-transfer-center` 通过（79 个单元测试、14 个 edge_auth 集成测试、15 个 import_worker 集成测试）；`npm run typecheck` 和 `npm run build`（`web/center-web/`）通过，构建仅有 ant-design-vue PURE 注释与 chunk size warning。
